# Platform Stack — How the 4 Platforms Connect

## Overview

The community runs across four platforms. Each has a distinct role. They are not interchangeable and should not drift into each other's territory.

```
LinkedIn  →  Public face. Discovery, credibility, content.
Telegram  →  Community hub. Discussion, bots, signals, coordination.
WhatsApp  →  India warm circle. Personal relationships, Mumbai chapter.
GitHub    →  Operating system. Docs, outputs, assignments, history.
```

---

## Platform Roles

### LinkedIn
**Role**: Public face of the community.

- Where the community is discovered by outsiders
- Where content is published to build credibility before someone joins
- Where case write-up summaries are posted after each session
- Where the founder's profile acts as the community's front door
- What people see when they Google the founder or the community name

**What it is NOT**: A discussion forum. A place to have conversations. A replacement for Telegram.

**Cadence**: 1 post per week minimum. Post types: frameworks, case breakdowns, signal takes, session recaps.

---

### Telegram
**Role**: Community operations hub.

- Where members have real conversations between sessions
- Where event coordination and reminders happen (via bots)
- Where weekly case prompts run (via bot)
- Where SC Signal drops every Monday (via bot)
- Where AMA questions are collected and ranked (via bot)
- Where new members are welcomed automatically (via bot)
- Where GitHub updates are announced (via GitHub Update Bot)
- Searchable history — members can find past discussions months later
- No phone number sharing required — members join via link

**Structure**:
- One main group for all members
- Pinned message: community intro, GitHub link, next session details
- Topics/threads (if using Telegram Topics): #sc-signals, #case-prompts, #events, #introductions

**What it is NOT**: A broadcast channel. A WhatsApp replacement. A customer support inbox.

---

### WhatsApp
**Role**: India warm circle only.

- Used exclusively for the Mumbai chapter's close circle
- High-touch, personal — people the founder or Satya know directly
- Not the community hub — Telegram is
- No bots, no automation — intentionally human
- Satya (India co-lead) owns this group

**Who is in it**: Mumbai-based members who the India co-lead has a personal relationship with. Maximum ~20-30 people.

**What it is NOT**: The main community channel. Open to anyone. A replacement for Telegram.

---

### GitHub
**Role**: The community's operating system and permanent record.

- Where all documentation lives (vision, charter, roadmap, team)
- Where every case write-up is published after each session
- Where frameworks, templates, and resources are stored
- Where the roadmap is tracked with checkboxes
- Where members are given responsibilities via folder ownership
- Where the community's history compounds over time
- Public — anyone can read it, which makes it a credibility signal

**Member assignment model**: As the community grows, active members are given ownership of specific folders:
  - Case Archivist → owns `/updates/`
  - Frameworks Curator → owns `/resources/`
  - Newsletter Lead → owns `/newsletter/` (to be created)
  - Chapter leads → own their chapter file in `/chapters/`

**What it is NOT**: A social platform. A place for casual conversation. Hidden — it should always be public.

## How the Platforms Connect

```
LinkedIn post published
    → Drives outsiders to founder's profile
    → Founder profile links to GitHub repo
    → GitHub repo shows full community depth
    → Interested person messages founder
    → Founder invites them to Telegram group
    → Welcome Bot greets them automatically
    → They join Mumbai circle via Satya (if India-based) → WhatsApp

Session happens
    → Case write-up pushed to GitHub /updates/
    → GitHub Update Bot notifies Telegram group automatically
    → Founder posts summary on LinkedIn
    → Summary links back to full write-up on GitHub

Weekly rhythm (no manual work after setup)
    → Monday: SC Signal Bot posts to Telegram
    → Wednesday: Case Prompt Bot posts to Telegram
    → Friday: Founder posts one LinkedIn piece
    → Ongoing: GitHub Update Bot connects outputs to community
```

---

## Platform Anti-Patterns to Avoid

| Anti-Pattern | Why It's a Problem |
|---|---|
| Posting the same content on all platforms | Each platform has a different audience and role. Telegram members are already followers — they don't need to see the LinkedIn post reposted. |
| Using WhatsApp as the main community hub | WhatsApp has no bots, no searchable history, no threads. It breaks down at 30+ people. |
| Keeping GitHub private | The whole point of GitHub is that it's a public credibility signal. Private repos defeat the purpose. |
| Running discussions on LinkedIn | LinkedIn comments are not a community. They're engagement metrics. Real discussion happens on Telegram. |
| Letting Telegram go quiet between sessions | This is why the bots exist. Silence kills communities. Automation prevents silence. |
